# Standard release player (version 1)

Step 10 uses this specification and `templates/player-template` as its canonical UI and behavior. Do not invent a new shell per production. The template defines the layout and behavior directly; no external production or reference project is required to interpret this standard. Timing, resolution, audio format and channel count are production-specific adapter inputs.

## Landing page

- Full viewport dark canvas background, centered production title, group, release/party information, role/name credits, Start button, Pouët/GitHub links and compact keyboard help. Match the template's spacing, typography and control placement. Only metadata, palette, original logos when supplied and production-specific geometry change.
- Animate the translated original first animation live behind a strong dark overlay. Use an independent instance/worker, a recovered or explicitly provisional cadence and a verified loop interval. Do not hardcode another production's rate/duration. No screenshot/video background or replacement procedural animation. Suspend it during playback and when the document is hidden; return to it on Stop. An unavailable original animation remains an explicit incomplete requirement rather than silently substituting a static frame.
- Credits remain visible and readable, with brighter names and muted but legible labels. Production-aligned accent colors apply consistently to credits, controls and diagnostics. Loading must not replace the title, release information or credits with different wording. Populate both initial packaged HTML and ready-state UI from the same metadata (displayTitle may differ from the browser-tab title). Only button availability/loading/error status changes. No persistent Ready badge. Preparing and failures remain visible and accessible. Start must enter the demo after one user gesture; errors must leave a usable page.

## Player behavior

- Live canvas fits the viewport with original display aspect and pixel geometry. Preserve the Pause/Resume, Stop, minus/plus15 seconds, continuous timeline, elapsed/total time, Fullscreen, Stats for nerds switch, Scale (1x/0.5x) and Volume controls in the template layout. Controls reveal on pointer/touch/keyboard activity and hide after inactivity; remain usable in fullscreen, on narrow screens and while keyboard-focused. Controls cannot be clipped offscreen.
- Space toggles pause, arrows seek15 seconds, F toggles fullscreen, Escape stops. Native range/select input keys retain their expected behavior. Stop returns to the animated landing page and restart begins from clean visual/audio state. Finite productions present the verified final frame and pause at the end. Open-ended productions declare duration:null, label the absence of a finite timeline and disable absolute scrubbing without inventing an ending.
- Capture slider values synchronously. RAF must never overwrite a held/dragged thumb. Commit on release/change; support pointer cancellation, touch and keyboard. Show the selected position immediately. Suspend advancement and mute/pause audio while preparing a seek; wait for both a matching-epoch frame and an audio acknowledgement before resuming. A paused seek stays paused; a playing seek resumes at the target, not target plus loading time. The latest rapid request wins. Stale frames cannot clear current pending state. Failures/timeouts/Stop settle pending requests and leave a recoverable UI.
- Seeking is standard for finite productions. Measure first; use sparse complete graphics AND audio checkpoints if replay latency is unsuitable. Record selected positions, restore+forward state/PCM comparisons, checkpoint bytes and p50/p95/max cue latency. Never fake a cue by moving only the slider or playing old audio. Checkpoints contain translated state, never captured pictures for playback.

## Stats for nerds

The switch reveals measured displayed-frame FPS (not a hardcoded target or RAF count), worker advance/render p95/max and relevant seek/queue diagnostics. Show zero/paused when paused. Distinguish browser presentation FPS from logical simulation cadence and audio clock.

For module productions, render a horizontally scrollable module pattern grid: channel headers, note/instrument/effect columns, adjacent rows, highlighted current row and module/order/pattern/row/tick heading. Support the actual format and arbitrary used channels. Decode original data for display only. Cursor events must come from original replay state and remain aligned after pause, seek and restart; never derive a guessed row solely from wall time or substitute a tracker library for sound playback. Diagnostics must not change original output (compare PCM/state with reads enabled/disabled).

`loadDiagnosticsResources()` on the video adapter optionally returns `{title, channels:[channelName,...], orders:[patternIndex,...], patterns:[rows,...]}`; each row contains channel cells `{note, instrument, effect}` as display strings. `diagnostics()` on the audio port returns structured-clone-safe original cursor `{order, row, tick}` and optional original device/voice fields. Worklet telemetry is bounded and read-only; keep format-specific decoders out of the shell. Non-module audio shows meaningful source-driven voice/device diagnostics in the same panel. Missing diagnostics and verified silence must be labeled truthfully; fake notes, voice counts, meters or an empty hidden canvas cannot satisfy this requirement.

## Package and acceptance

Use one `release/` directory for all attempts, never release-v2/final/new siblings. Root `index.html` and `player/index.html` must both enter the same production, including under a URL subdirectory. Use relative assets. Ship only required production code/data and current checkpoint build. Disable fixture/validation route selection and exclude examples/tests/oracles/captures, screenshots used as frames, unused builds and external runtime dependencies. Keep a SHA-256/size manifest and review reports; do not label reports PASS before checks finish. The template's build-release.mjs prepares the standard directory layout; it is not fidelity certification.

Run the browser harness against the packaged URL with independent original-execution/verified-renderer frame expectations covering scenes, handoffs and ending. Run real pointer and keyboard UI checks too: API seek checks alone do not establish that the visible timeline responds correctly to user input. Include both root/player entries, subdirectory loading, landing motion/darkness/credits, Start, hold/drag/cancel, paused/running/rapid/backward seeks, resume, stop/restart, original-code audio, tracker cursor, FPS, volume/scale, fullscreen and narrow layout. Record skipped/unsupported cases explicitly as incomplete, not PASS. Add full integrated run and per-phase performance coverage. Do not equate infrastructure-fixture results with production evidence. A final packaged human audiovisual review remains required.

## Delivery checklist and deployment

Record each item's result, evidence path and remaining limits in release/README.md: standard UI; both entry routes/subdirectory; original live background; controls and navigation; original audio+cursor; independent canvas cases; restore/forward checks; full-run sync/ending; page/worker/seek latency; manifest/no development leaks; human review.

Prepare exact commands, with real production paths and ports: `node player/build-release.mjs`, `node release/serve.mjs`, `node player/tests/browser.mjs --url http://127.0.0.1:1997/ --expectations <agent-prepared-file> --output release/browser-acceptance.json`. The builder must reject an unconfigured adapter. Serve via HTTP locally; AudioWorklet requires HTTPS in deployment (localhost is allowed). Set the static host's publish directory to release with no build step. Serve .mjs as JavaScript, binary/music/checkpoint files as bytes; do not set Content-Encoding:gzip for files decompressed explicitly by the player. Preserve paths, disable SPA fallback for missing assets, verify deployed root/seek/audio. Publication is human-owned. Never publish automatically.

Step 10 is COMPLETE only after both prior milestones, all required automated checks, full integration and human packaged review. Otherwise record INCOMPLETE or ACTION NEEDED and one concrete next action. A started server, pending background test, attractive screenshot or prepared checklist does not complete it.

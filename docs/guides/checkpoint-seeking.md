# Seeking by replay or complete-state checkpoints

Start with deterministic reset-and-advance using the translated code. Measure worst-case seeking in the actual browser. If it is already fast enough, no stored checkpoints are required. If not, choose checkpoint spacing from measured simulation cost and memory/state size; there is no universal 15-second interval, file size, or instant-resume guarantee.

## Preserve state, not recorded frames

A checkpoint restores computation: memory, palette/video state, scene/feedback buffers, timers, random seeds, audio replay/device state, and FPU state where they affect future output. Some high-level ports need a compact algorithm state rather than a CPU register file. Serialize exactly what the production uses and document omissions; captured-frame sequences and video are never substitutes for live simulation.

Prefer checkpoints generated by verified translated execution. Original capture snapshots are reference evidence and may contain unknown initialization dependencies; injecting them into a port does not prove that startup or preceding scenes were translated.

## Optional memory codec

`runtime/checkpoint.mjs` provides a sparse 4 KiB page helper, including a partial final page, plus explicit JSON-serialized extra state. It does not automatically discover or restore FPU, sound/device, palette, or other future-affecting state. The adapter supplies and restores those fields itself. Do not pass raw BigInts or typed arrays without an explicit lossless serialization convention.

Use `encodeVerifiedCheckpoint()` and `restoreVerifiedCheckpoint()` to validate the exact startup-baseline SHA-256. The lower-level synchronous functions do not prove baseline identity by themselves. The current format is schema 2; older unverified memory helpers need migration, not an automatic claim of compatibility.

Restore the nearest valid earlier checkpoint, simulate forward to the requested presentation time, then draw the live frame and restore/replay sound to the same position. Keep the loading indicator until the requested frame arrives. Epoch IDs reject stale results from earlier seeks; expensive adapters may additionally cancel obsolete catch-up work.

## Required checks

Compare continuous playback with reset-and-advance and checkpoint-restore-and-advance at representative times, across transitions, near endings, and while paused. Include backwards seeks and repeated seeks, and compare all declared output and future-affecting state. Verify the next several frames after restore, not only the immediate picture. Test sound phases/loops and both work orders (graphics first or audio first) where supported.

Record actual latency, checkpoint size, and which state is covered. A passing memory codec fixture is infrastructure evidence, not proof that a production's checkpoint contains complete state.
